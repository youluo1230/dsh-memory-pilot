# 决策模型的能力边界

决策模型是一个窄判断引擎：给定一段状态和一组带判据的选项，返回一个带校准概率的选择，典型延迟约 100 毫秒。它不理解长上下文，不做推理链，不生成文本。

这条边界决定了它能用在哪儿。本文记录判断标准，避免日后把不该它做的事塞给它。

## 适合的形态

一个符合条件的判断，同时具备四个特征：

1. **封闭选项** — 答案是"其中哪一个"，不是自由文本。开放问题需要生成，那是主模型的事。
2. **判据可写** — 每个选项能用一两句话说明什么情况选它。写不出判据，说明问题还没想清楚。
3. **单点判断** — 不需要多步推导。需要"先看 A 再看 B 才能定"的事情，是推理，不是分级。
4. **错了有兜底** — 误判的代价可由上层逻辑吸收。需要绝对正确的地方不该单独依赖它。

## 不适合的形态

| 形态 | 为什么不行 | 应该交给 |
|---|---|---|
| 开放式问答 | 要生成内容，不是选一个 | 主模型 |
| 多步推理 | 没有推理链，只有一次前向 | 主模型 |
| 长文档理解 | 上下文窗口小，只看得到给定状态 | 主模型 |
| 需要解释理由 | 只返回选择与概率，不返回论证 | 主模型 |
| 高风险不可逆决策 | 校准概率不等于正确 | 人，或主模型 + 人 |

## 人机交互原则

判断自动化程度的唯一标准是**误判的代价能否被吸收**，不是判断本身难不难。

- **静默执行** — 误判代价低且可回滚（选错检索范围、误判紧急程度）。用户不该看到任何提示。
- **静默执行 + 事后可见** — 同上，但要能在决策记录里查到它做了什么。这是默认档位。
- **请示用户** — 只有误判会造成不可回滚的后果（删除数据、对外发送、花钱）。

绝大多数判断落在前两档。把第三档压到最小，是这个系统可用的前提：一个每步都要点确认的助手，用户会习惯性点"同意"，授权本身也就失效了。

## 当前使用者

| 判断 | 档位 | 说明 |
|---|---|---|
| 是否需要记忆 | 静默执行 + 事后可见 | 判断错只是多查或少查一次 |
| 检索哪个范围 | 静默执行 + 事后可见 | 同上 |
| 是否值得记住 | 静默执行 + 事后可见 | 写入可去重、可遗忘 |
